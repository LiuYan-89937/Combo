# 应用场景

FastAgentFactory 的核心应用场景是完全本地化的个人智能助手。它不是单一聊天机器人，而是把长期对话、跨会话记忆、本地知识、工具调用、多 Agent 协作，以及 Agent 的设计、生成、运行、治理和演进统一到 AgentPackage 的工程平台。

## 1. 个人智能助手

适用于文件检视、资料整理、内容生成、数据查询、周期提醒和多工具协同等日常任务。助手可以在新会话中检索与当前请求相关的长期记忆，延续用户偏好和历史决策；需要外部事实或文件内容时，仍通过对应工具显式取证。

- 推荐 Pattern：`react_agent`。
- 原因：任务路径难以预先固定，模型需要在“思考—调用工具—观察结果—继续处理”之间动态循环。
- 后端支撑：动态工具可见性、ToolGateway、工作区文件工具、MCP/SkillHub 扩展、Checkpoint 和中断恢复。

典型例子包括个人工作区助手、私有资料助手、日程与文档助手、邮件与简报助手，以及带审批的自动化助手。

## 2. 金融研究示例

仓库内置 A 股盘面雷达、A 股上市公司研究员和 A 股持仓风险管家，用于展示个人智能助手如何组织专业子 Agent 完成复杂研究任务。

- 盘面雷达获取市场宽度、成交额、板块和领涨结构，并生成可保存的市场简报。
- 上市公司研究员围绕单家公司整合行情、财务、趋势和用户挂载资料，形成证据化报告。
- 持仓风险管家计算集中度、波动率、回撤、相关性，并执行用户明确指定的压力情景。
- 主助手可以并行分工、验收交付物、合并完整报告，并在用户授权后通过已配置邮箱发送。

所有输出必须包含数据来源、数据时间、异常说明和风险声明，仅用于研究与系统能力演示，不构成投资建议。

## 3. 多步骤研究与交付

适用于需要先拆解任务、逐步取证、持续更新进度并最终形成报告的工作。

- 推荐 Pattern：`plan_and_execute`。
- 原因：系统需要显式维护动态计划，区分规划、执行和最终交付，并让执行节点按当前步骤调用业务工具。
- 后端支撑：`runtime_plan`、节点级工具权限、计划状态持久化、Artifact、Knowledge 和 Trace。

典型例子包括公司研究、尽调、风险分析、长文报告、跨来源信息核验和分阶段数据处理。

## 4. 企业知识与私有资料问答

适用于挂载本地资料、内部规范、研究文档或结构化知识源后进行检索和引用。

- Knowledge Contract 负责构建知识运行时和后台摄取 worker。
- `knowledge` 工具负责搜索、打开和读取命中内容。
- Context/Memory 可提供与当前请求相关的跨会话记忆，但不应替代显式知识检索。
- Resource Contract 可保存数据库、API 或外部知识服务所需的受控配置。

知识库“已配置”不等于知识全文“每轮自动注入”。默认工程边界应是：检索结果按需进入当前任务上下文，避免无差别消耗 token，也降低陈旧信息污染回答的风险。

## 5. 定时任务与持续监测

适用于定时生成简报、周期检查、监测数据变化或按计划触发 AgentPackage。

- Scheduler Contract 声明调度能力及持久化位置。
- Scheduler Runtime 管理 job、run、lease、失败策略和执行反馈。
- 无人值守运行使用独立的 scheduler session，避免混入普通聊天记录。
- 调度触发仍受工具权限、Resource 完整性和审批策略约束。

典型例子包括盘前/收盘简报、风险复查、业务指标巡检和周期性资料汇总。

## 6. 带交付物的内容生产

适用于输出 Markdown、报告、图片、结构化文件或其他可保存结果的任务。

- Artifact Contract 提供统一工件存储。
- 文件写入和模型工具生成的结果通过运行时根目录、会话目录和工件引用管理。
- 生图能力通过 Model Tool Binding 声明，不属于聊天模型的隐式能力。
- 最终交付节点可获得交付工具，但不应拥有与交付无关的高风险工具。

## 7. Agent 批量制造与业务模板化

适用于把自然语言需求、附件和业务规则转换为可发布 AgentPackage。

制造流程会分析目标、选择 Pattern、创建隔离作者工作区，并通过作者工具生成 Assembly、Contract、Tool、Skill 和知识文件，然后执行静态验证。它适合平台管理员、Agent 工程师和业务方案团队建立可复用的 Agent 产品线。

## 8. 线上 Agent 的受控进化

适用于已有 Agent 出现能力缺口、工具错误、Prompt 不合理或业务要求变化时进行定向修改。

进化流程以已有包为目标，结合用户目标和历史失败 Trace 做相关性判断，再限定修改范围并复用制造工作流。该机制适合持续优化，但不能把所有失败都归因于 AgentPackage：基础设施错误、模型服务不可用或 RuntimeKernel 故障应先在对应层修复。

## 9. 多 Agent 协作

适用于一个主任务需要拆成多个专业子任务，由不同 AgentPackage 分工处理并汇总交付。

- Agent Group 描述成员和协作结构。
- Collaboration Orchestrator 管理任务派发、授权材料、运行状态和结果回收。
- Worker 只获得被授权的工件与协作上下文，避免直接共享整个主会话或宿主工作区。
- 协作场景可在运行时增加协作工具，并排除不适合 worker 的系统工具。

## 场景与 Pattern 选择

| 判断条件 | `react_agent` | `plan_and_execute` |
| --- | --- | --- |
| 任务长度 | 短到中等，路径动态 | 中到长，需要显式步骤 |
| 计划可见性 | 不要求独立计划状态 | 需要创建、检查和更新计划 |
| 工具调用 | 对话循环中自由选择 | 按 planner/executor/final 的职责分层 |
| 用户补充信息 | 在对话中自然询问 | planner 可进入等待输入状态 |
| 最终交付 | answer 直接完成 | final_answer 汇总计划证据后交付 |
| 典型任务 | 聊天、检索、即时操作 | 研究、分析、复杂执行、报告 |

Pattern 的选择不是按“模型强弱”决定，而是按任务是否需要独立、可持久化、可审计的计划状态决定。固定业务流程若节点和转移条件完全确定，应进一步设计专用 Pattern 或子图，而不是把所有确定性流程都塞进 ReAct。

## 不适合直接交给 Agent 的场景

- 未建立审批和权限边界的高风险外部写操作。
- 要求强事务、严格实时性或确定性响应的核心交易链路。
- 没有数据来源，却要求模型给出实时事实或保证性结论的任务。
- 依赖未配置模型、Resource、MCP 服务或知识索引的能力。

这些场景可以由 FastAgentFactory 编排辅助流程，但不能仅靠 Prompt 消除底层系统约束。
